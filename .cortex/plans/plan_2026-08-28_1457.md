## Backend Plan

The existing foundation is solid — auth, availability, scheduling algorithm, and Prisma schema are all in place. The main gaps are: **commute awareness**, **PA quotas**, and **admin heatmap/manual assignment support**. Here's what I'll build:

### 1. Schema changes (Prisma migration)
- Add `community` field to `User` (for PAs — where they're based)
- Add `community` field to `School` (where workshops happen)
- Use a string enum approach (not a DB enum) so adding communities is just a code change
- Add `monthlyQuota` field to `User` (default 4 — configurable per PA)
- Change `Workshop.minPAs` default from 1 → 3

### 2. Commute module (`src/lib/scheduling/commute.ts`)
- Define community list: UBC, Burnaby, Vancouver, North Vancouver, Richmond, Surrey
- Travel time matrix (minutes) between all pairs
- `getCommuteCost(from, to)` — returns minutes
- `canReachInTime(paCommunity, schoolCommunity, buffer)` — boolean check
- Extensible: adding a community = add one row/column to the matrix

### 3. Quota module (`src/lib/scheduling/quota.ts`)
- `getAssignmentCounts(paIds, cycleId)` — how many workshops each PA has this cycle
- `sortByQuotaDeficit(paIds, counts, quotas)` — prioritize under-scheduled PAs
- Used by the scheduler to distribute work fairly

### 4. Enhanced scheduling algorithm (`src/lib/scheduling/algorithm.ts`)
- Add commute filtering: exclude PAs whose community → school community travel is infeasible
- Add quota-aware sorting: prefer PAs furthest below their monthly quota
- Keep the greedy approach but with smarter candidate ordering

### 5. Heatmap data module (`src/lib/scheduling/heatmap.ts`)
- `getAvailabilityHeatmap(cycleId)` — for each (day, slot), count PAs available (with commute filter per school)
- `getPAsBySlot(dayOfWeek, startMin, schoolCommunity?)` — list PAs available at a specific time, optionally filtered by reachable community
- This powers the admin "lettucemeet" view

### 6. Manual assignment module (`src/lib/scheduling/assignments.ts`)
- `assignPA(workshopId, paId)` — admin manually assigns a PA
- `unassignPA(workshopId, paId)` — admin removes a PA
- `swapPA(workshopId, oldPaId, newPaId)` — admin swaps one PA for another
- `getAvailablePAsForWorkshop(workshopId)` — which PAs could cover this workshop (time + commute + not already booked)

### 7. Zod schemas
- `src/lib/schemas/communities.ts` — community validation
- Update `src/lib/schemas/scheduling.ts` — add assignment action schemas

### 8. Update existing schemas
- `teachers.ts` and `schools.ts` — add community field to create/update schemas

No frontend changes — this is purely backend/lib code.
