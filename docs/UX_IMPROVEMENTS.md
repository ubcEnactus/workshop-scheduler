# Workflow usability review — 16 September 2026

The largest opportunity is reducing repeated setup and page changes. Keep the navy/amber design, but make the monthly schedule the working surface and give recurring availability a faster editor. More summary cards would not help these tasks.

## Evidence and scope

Reviewed the protected Vercel preview as admin and PA, captured eight desktop/mobile states, followed a school-filtered month into planning, and checked the corresponding forms, links and Server Actions. Teacher access remains intentionally view-only. This is a workflow inspection, not a timed study with users; the targets below are proposed acceptance criteria.

## Suggested implementation order

1. **Continuity and compact workspace:** preserve navigation context; make counts/filter controls useful; retain form input on validation errors; put creation behind an explicit action. This removes backtracking without changing scheduling rules.
2. **Faster repeated input:** availability ranges/day copy and bulk quota saves. These offer the largest reduction in repetitive entry.
3. **Scheduling in place:** staffing side panel and class-aware date suggestions, followed by reviewed bulk publication and the dashboard task list.

For example, staffing five drafts currently repeats four pointer actions per workshop from the list (open detail, expand candidates, assign, return): about 20 actions, excluding scrolling and choosing among candidates. A row-side-panel flow targets about 10 (open, assign). These are interaction counts for the described flow, not measured task-time improvements. Extra review remains appropriate when publishing or changing published work.

## Validation for the usability work

- Cover context through header links, sidebar links, successful saves, validation failures, Back and reload, including a filtered month other than the current month.
- Test mobile at 390px and narrow desktop, 200% zoom, keyboard-only operation, focus return, announced errors, pending/duplicate submissions and axe checks. Contained horizontal scrolling passing an overflow test does not make the availability editor easy to use.
- Availability range tests must cover adjacent/overlapping ranges, duplicate copies, empty days, clearing all, slot boundaries and saved versus unsaved state. Preserve recurring Vancouver wall-clock semantics.
- Bulk quotas need mixed valid/invalid rows, blank versus zero, inactive PAs, month boundaries and stale writes. Define atomic save behavior before implementation.
- Staffing panels and bulk publication must keep role authorization, draft privacy, capacity, quotas, full-duration availability, day spacing, locks and concurrency checks. A faster UI cannot bypass these rules.
- Suggested dates need short availability windows, no valid dates, leap months, Vancouver DST, duplicate submissions and existing planned/completed/cancelled occurrences. Suggestions are not school holiday knowledge.

The current automated suite covers the scheduling constraints and main role workflows, not every possible human interaction or every future feature above. The day-spacing coverage includes exact thresholds, both date directions, DST, month/year/leap boundaries, different UTC versus Vancouver dates, same-school different-class visits, concurrent assignments, matching, publication, replacement, rescheduling, cancellation/completion, invalid settings and migration conversion. The follow-up adds browser acceptance tests for the implemented workflows. Real-user task-completion studies remain useful.
